# English Path

До версии 2.0 (09.11.2026) приложение называлось Oxford Cards. Сначала прочитать общие правила `C:\Workspace\AGENTS.md`,
затем `README.md`. Для правок словаря читать `DATA-SOURCES.md`: менять источник исправлений и запускать импорт,
сохраняя идентификаторы карточек.

Внутренние имена остались от Oxford Cards намеренно: схема `oxford://app` (на её адресе лежит прогресс в Local Storage),
ключ `oxford-cards:v1`, мосты `window.oxford*`, каналы `oxford:*`. Их смена потеряет прогресс — не переименовывать.

## Рабочее приложение и прогресс

Иван пользуется установленным приложением: `C:\Program Files\English Path\English Path.exe`, ярлыки на рабочем столе
и в «Пуске» (с 09.11.2026). После изменения приложения: `npm run build:setup` и установить `release\English-Path-Setup.exe`
поверх; установщик спрашивает права администратора — его проходит Иван. Если менялись записи озвучки, сначала
`npm run build:voice-pack` и выложить пакет (раздел «Релиз на GitHub»), иначе установленное приложение не скачает новые записи.
Запускать установщик и приложение в обычном пользовательском окружении, а не дочерним процессом терминала агента.
Не захватывать экран без необходимости; пользователь предпочитает файловые операции и API.

Прогресс — `%APPDATA%\English Path`; при первом запуске 2.0 он скопирован из `%APPDATA%\Oxford Cards` (та папка
оставлена как резервная копия). Записи озвучки — `%LOCALAPPDATA%\English Path\voices`.

28 октября 2026 года подтверждено: процессы, запущенные терминалом агента, и обычные процессы Проводника видели разные
файлы по одному логическому пути в `%APPDATA%`. Не считать чтение профиля из терминала достоверным чтением текущего
пользовательского прогресса и не восстанавливать старые копии без сверки.

Проверенный запуск без UI-автоматизации — `scripts/run-via-explorer.ps1 -File <полный путь> [-Arguments …] [-Directory …]`:
скрипт берёт открытое окно Проводника через `Shell.Application.Windows()` и вызывает его
`Document.Application.ShellExecute`. Вызов `ShellExecute` на новом `Shell.Application` запускает процесс в окружении
агента и проблему не решает. При отсутствии окна Проводника не подменять этот способ незаметно запуском из терминала.
Прогресс читается так же: `node_modules\electron\dist\electron.exe <папка>\read.cjs "English Path"` через этот скрипт
(образец `read.cjs` — `work/progress-before-english-path-20261109-060701/`); он копирует Local Storage в новую папку
`<профиль>-<время>` рядом с собой и пишет туда `report.json` с числом карточек, ответов и глаголов (старые копии не
удаляет: Windows может ещё держать их файлы, 09.11.2026).

Исследования, диагностические копии и вспомогательные скрипты хранить в игнорируемом `work/`. Перед операциями
с прогрессом делать копию, проверять исходное и полученное количество карточек и записей истории. Не включать личный
прогресс в сборку или git.

## Релиз на GitHub

Репозиторий — `MaybeKrat/english-path` (переименован из `oxford-cards` 09.11.2026; старые ссылки GitHub перенаправляет).

1. Поднять версию: `npm version <версия> --no-git-tag-version`.
2. Если менялись записи: `npm run build:voice-pack` — обновится `desktop/voice-pack.json` (новый релиз `voices-<хеш>`).
3. Собрать установщик: копия прогресса, `npm run build:setup`, установка через Проводник, сверка прогресса.
4. Закоммитить (вместе с `desktop/voice-pack.json`, если он изменился) сообщением «Release English Path <версия>»,
   поставить метку `v<версия>` и отправить: `git push origin main v<версия>`.
5. Описание релиза на русском записать в `work/release-<версия>/notes.md` и выполнить
   `node scripts/publish-release.mjs work/release-<версия>/notes.md`. Скрипт сначала выкладывает пакет озвучки в релиз
   `voices-<хеш>` (если его ещё нет; этот релиз не становится «последним»), затем создаёт релиз версии и прикладывает
   `release\English-Path-Setup.exe` (на это имя ссылается README). Без аргумента выкладывает только озвучку.
   Повторный запуск безопасен.

Пакет озвучки должен быть выложен раньше, чем кто-то установит версию с новым `voice-pack.json`.

Токен GitHub скрипт берёт сам через `git credential fill` — тот же вход, которым пользуется `git push`; токен никуда
не выводится. Искать доступ к GitHub в `context/accounts.md` или в переписках других сессий не нужно: такой поиск
классификатор Claude Code блокирует как поиск секретов (31.10.2026). `gh` на машине не установлен.
